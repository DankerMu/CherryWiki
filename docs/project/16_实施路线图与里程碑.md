# 16. 实施路线图与里程碑

## 1. 总体原则

本项目不设“实验性 Phase 1”口径，而按“分阶段交付成品”推进。Phase 1 是最小可用成品，要求可部署、可登录、可上传、可自动生成 Wiki、可检索并完成 Chat 引用。

```text
Phase 1  Cherry Web + Graphify 自动生成 + 只读 Wiki + 向量/BM25 检索 + Chat 引用
Phase 2  Docmost Fork 协作编辑 + 双向同步 + 人工编辑
Phase 3  GraphRAG 完整闭环 + 图索引 + 图路径解释
Phase 4  知识治理与高级能力 + 审计 + 安全增强 + MCP Gateway
```

## 2. Phase 1：最小可用成品

### 2.1 目标

交付一个无需 Docmost 的可运行系统：上传资料后自动归档、解析、触发 Graphify 生成 Wiki；Cherry Web 内置只读 Wiki；Chat 基于 Wiki 向量 + BM25 检索回答并引用页面。

### 2.2 交付物

| 模块 | 交付物 |
|---|---|
| Cherry Web | 登录、Space 切换、只读 Wiki、Chat 页面、引用展示。遵循 UI 设计规范（`docs/design/12_UI设计规范_CherryStudio风格对齐.md`）。 |
| Admin | 用户、Group、Space、模型、任务管理。遵循 UI 设计规范。 |
| Upload | 文件上传、去重、Source Archive、上传进度。 |
| Ingestion | 文件校验、解析、归档元数据、Graphify job 触发。 |
| Graphify Worker | 调用 graphify Python API + LLM 语义提取生成知识图谱和 Wiki（见 Doc 22 勘误）。 |
| Wiki Core | Canonical Wiki Repo、页面版本、发布状态。 |
| Indexer | Wiki chunk、embedding、BM25 索引。 |
| Chat | 流式回答、Wiki citation、无权限过滤。 |
| Deployment | Docker Compose、env、Nginx 样例。 |

### 2.3 退出标准

1. 10 个并发用户可登录并使用 Chat。
2. 上传资料后能自动生成 Wiki 页面。
3. Cherry Web 可浏览只读 Wiki 页面。
4. Chat 回答只引用 Published Wiki 页面。
5. 无权限 Space 内容不会出现在 Chat、Wiki、搜索中。
6. Graphify 失败不影响上一成功索引。
7. Docker Compose 可一键启动完整环境。

### 2.4 依赖关系

- 必须先完成 Cherry Web/API/Auth 基础。
- Graphify Worker 可在独立容器中运行。
- Indexer 必须依赖 Wiki Page 发布版本。
- Docmost 不进入 Phase 1 关键路径。

### 2.5 预估工作量范围

| 领域 | 工作量 |
|---|---:|
| Web + Admin | 4-6 周 |
| API/Auth/DB | 4-6 周 |
| Upload/Ingestion/Archive | 3-4 周 |
| Graphify Worker | 2-4 周 |
| Wiki/Indexer/Chat RAG | 4-6 周 |
| DevOps/QA | 2-3 周 |

## 3. Phase 2：Docmost 协作编辑

### 3.1 目标

Fork Docmost 开源版，新增内部 Bridge endpoint 和页面保存 webhook，实现 Graphify Wiki 与 Docmost 的双向同步，支持人工编辑。

### 3.2 交付物

| 模块 | 交付物 |
|---|---|
| Docmost Fork | `external/docmost/`、`/api/internal/bridge/`、save webhook。 |
| Bridge | Graphify → Docmost 导入、Docmost → Repo 回写。 |
| Space Mapping | Cherry Space ↔ Docmost Space。 |
| Block Ownership | Graphify managed / human curated / locked 区块。 |
| Candidate Update | Graphify 更新不覆盖人工修订，进入候选更新。 |
| Consistency | page_version / index_version / graphify_run_id 一致性检查。 |

### 3.3 退出标准

1. Graphify 页面可导入 Docmost。
2. Docmost 页面保存后可回写 Canonical Wiki Repo。
3. 人工区块不会被 Graphify 覆盖。
4. 同步失败可重试，重复 webhook 幂等。
5. 权限映射通过端到端测试。
6. Docmost upstream rebase 后回归测试通过。

### 3.4 依赖关系

- Phase 1 的 Wiki Core、版本模型、任务系统。
- Docmost Fork 基线 commit 决策。
- Bridge secret、内部网络、安全策略。

### 3.5 预估工作量范围

| 领域 | 工作量 |
|---|---:|
| Docmost Fork Bridge | 3-5 周 |
| 双向同步 | 4-6 周 |
| 冲突合并/候选更新 | 3-5 周 |
| 权限一致性 | 2-3 周 |
| QA 回归 | 2-3 周 |

## 4. Phase 3：GraphRAG 完整闭环

### 4.1 目标

导入 `graph.json` 到图表，实现节点/边/路径/社区检索，与 Vector/BM25 融合，并在 Chat UI 中展示图路径解释和关系置信度。

### 4.2 交付物

| 模块 | 交付物 |
|---|---|
| graph-core | `GraphRepository`、`PgGraphRepository`、schema import。 |
| 图索引 | `graph_nodes`、`graph_edges`、`graph_communities`。 |
| GraphRAG | Vector + BM25 + Graph 混合检索、rerank、context packing。 |
| Path UI | 图路径解释、节点/边详情、置信度展示。 |
| Retrieval Trace | 管理员检索调试。 |

### 4.3 退出标准

1. `graph.json` 可稳定导入图表。
2. 关系型问题优先返回路径解释。
3. `EXTRACTED / INFERRED / AMBIGUOUS` 显示正确。
4. GraphRAG 检索 P95 < 1.5s。
5. 无权限节点、边、路径不可见。

### 4.4 依赖关系

- Graphify Output Schema v1 契约。
- Phase 2 的版本一致性字段。
- `graph-core` Repository 接口。

### 4.5 预估工作量范围

| 领域 | 工作量 |
|---|---:|
| graph-core/import | 3-4 周 |
| GraphRAG/rerank | 4-6 周 |
| 图谱 UI | 3-5 周 |
| 性能优化 | 2-4 周 |

## 5. Phase 4：知识治理与高级功能

### 5.1 目标

补齐审计、安全增强、知识质量治理、MCP Gateway、备份恢复，使系统进入可长期维护状态。

### 5.2 交付物

| 模块 | 交付物 |
|---|---|
| Audit | 完整审计日志、检索追踪、任务追踪。 |
| Security | 上传沙箱、URL SSRF 防护、密钥轮换、权限一致性熔断。 |
| Knowledge Governance | 低置信关系审核、重复页面合并建议、知识冲突检测。 |
| MCP Gateway | Agent 工具链、Graphify MCP 兼容、工具权限策略。 |
| Backup/Restore | DB、MinIO、Wiki Repo、Graphify output 备份恢复脚本。 |
| Observability | Metrics、logs、traces、告警。 |

### 5.3 退出标准

1. 可完成备份恢复演练。
2. 可审计任意回答的引用、检索候选、图路径和权限过滤。
3. 低置信关系可人工审核。
4. 重复页面和知识冲突可进入治理队列。
5. MCP Gateway 工具调用有权限和审计。

### 5.4 预估工作量范围

| 领域 | 工作量 |
|---|---:|
| 安全与审计 | 4-6 周 |
| 知识治理 | 4-8 周 |
| MCP Gateway | 3-5 周 |
| 备份恢复/观测 | 3-4 周 |
