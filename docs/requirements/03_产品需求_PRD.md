# 03. 产品需求 PRD

## 1. 产品名称

暂定：CherryGraph Studio

## 2. 产品定位

CherryGraph Studio 是一个 Docker 化部署的多用户 AI 工作台，基于 Cherry Studio 社区版 Fork 重构为 Web 平台，以 Graphify Wiki 作为唯一知识源，使用 Docmost 提供多人协作 Wiki 编辑体验，并通过 GraphRAG 为聊天、Agent 和知识检索提供支撑。

## 3. 用户角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 普通用户 | 使用 AI 聊天、检索 Wiki、查看引用 | 快速获得基于内部知识的准确回答。 |
| 知识编辑者 | 上传资料、编辑 Wiki、审核生成内容 | 维护 Wiki 准确性和可读性。 |
| 空间管理员 | 管理某个 Space 的成员、页面、资料和索引 | 控制本空间知识质量和权限。 |
| 平台管理员 | 管理模型、用户、分组、任务、系统配置 | 保证平台稳定、安全、可审计。 |
| 开发者/运维 | 部署、二开、排障、扩展 | 清晰的模块边界、日志、监控和规范。 |

## 4. 用户故事

### 4.1 普通用户

1. 作为普通用户，我可以登录 Cherry Web，选择一个有权限的知识空间，提出问题。
2. 作为普通用户，我可以看到回答引用了哪些 Wiki 页面、哪些段落和哪些图谱路径。
3. 作为普通用户，我可以点击引用跳转到 Docmost Wiki 页面。
4. 作为普通用户，我可以查看与问题相关的概念节点、相邻知识和推荐阅读。
5. 作为普通用户，我不能看到无权限空间的页面、引用、节点或图谱路径。

### 4.2 知识编辑者

1. 作为知识编辑者，我可以上传 PDF、DOCX、Markdown、图片、网页链接或 ZIP。
2. 作为知识编辑者，我可以看到文件归档、解析、Graphify 运行、Wiki 生成、索引更新的状态。
3. 作为知识编辑者，我可以在 Docmost 中修订 Graphify 生成的 Wiki 页面。（Phase 2+）
4. 作为知识编辑者，我可以查看 Graphify 的候选更新，并决定接受、拒绝或手动合并。（Phase 2+）
5. 作为知识编辑者，我可以标记页面为已验证、待复核、已废弃。（Phase 2+）

### 4.3 空间管理员

1. 作为空间管理员，我可以配置 Space 的成员和权限。
2. 作为空间管理员，我可以触发某个 Space 的 Graphify 全量重建或增量更新。
3. 作为空间管理员，我可以查看 Graphify Run 的输出、失败原因和成本。
4. 作为空间管理员，我可以查看低置信关系、歧义关系和重复页面建议。
5. 作为空间管理员，我可以回滚 Wiki 页面到某个版本。

### 4.4 平台管理员

1. 作为平台管理员，我可以创建和管理用户、分组、角色。
2. 作为平台管理员，我可以集中配置模型服务、Embedding 模型、Rerank 模型。
3. 作为平台管理员，我可以查看所有任务队列、失败任务、运行日志和审计日志。
4. 作为平台管理员，我可以配置全局安全策略、上传限制、索引策略和备份策略。
5. 作为平台管理员，我可以导出系统状态和知识库统计报告。

## 5. 功能范围

### 5.1 Cherry Web 聊天

| 功能 | 优先级 | 说明 |
|---|---|---|
| 登录后聊天 | P0 | 支持流式输出、会话历史、模型选择。 |
| 空间/知识范围选择 | P0 | 用户只能选择有权限的 Space。 |
| 引用 Wiki 页面 | P0 | 回答必须返回引用页面、段落和版本。 |
| 图谱路径解释 | P1 | 展示答案涉及的节点、边、路径。 |
| 多模型对比 | P2 | 延后实现。 |
| Agent 工具调用 | P1 | 支持 Graphify/Docmost/MCP 工具。 |

### 5.2 Graphify Wiki

| 功能 | 优先级 | 说明 |
|---|---|---|
| 自动生成 Wiki | P0 | 使用 Graphify `--wiki` 输出页面。 |
| Canonical Wiki Repo | P0 | Git/文件系统存储规范 Markdown。 |
| 人工修订回写 | P0 | Docmost 编辑后同步回 Repo。 |
| 增量更新 | P0 | 文件或页面变化后触发 Graphify update。 |
| 差异合并 | P1 | 防止覆盖人工内容。 |
| 低置信关系审核 | P1 | EXTRACTED/INFERRED/AMBIGUOUS 分级治理。 |

### 5.3 资料上传归档

| 功能 | 优先级 | 说明 |
|---|---|---|
| 多格式上传 | P0 | PDF、DOCX、MD、TXT、图片、ZIP。 |
| 归档存储 | P0 | 原文件 immutable archive。 |
| 自动分类 | P1 | 按 Space、主题、文件类型、来源等归档。 |
| 解析为 Markdown/文本 | P0 | 作为 Graphify 输入。 |
| 重复文件检测 | P0 | SHA256 去重。 |
| 恶意文件检测 | P1 | ClamAV 或企业安全网关。 |

### 5.4 Docmost Shell（Phase 2 交付）

| 功能 | 优先级 | 说明 |
|---|---|---|

| Spaces 对应知识空间 | P2 | 每个知识域对应一个 Docmost Space。 |
| 页面导入导出 | P2 | Markdown/HTML/ZIP 互转。 |
| Bridge 同步 | P2 | 与 Canonical Wiki Repo 双向同步。 |
| 权限映射 | P2 | Docmost Group ↔ Cherry Group。 |
| Bridge 接入 | P2 | Fork Docmost 开源版并实现内部 Bridge endpoint。 |

### 5.5 管理后台

| 功能 | 优先级 | 说明 |
|---|---|---|
| 用户/分组/角色 | P0 | 支持 RBAC。 |
| 模型配置 | P0 | Chat、Embedding、Rerank 模型。 |
| Space 管理 | P0 | 绑定权限、Graphify Corpus（Docmost Space 绑定为 Phase 2）。 |
| Graphify 任务管理 | P0 | 创建、取消、重试、查看日志。 |
| 索引管理 | P0 | 触发重建、查看版本。 |
| 审计日志 | P0 | 登录、上传、编辑、删除、问答、权限变更。 |

## 6. 关键流程需求

### 6.1 上传资料流程

1. 用户选择 Space 并上传文件。
2. 系统校验文件大小、类型、权限和重复状态。
3. 原文件写入 Source Archive，并记录 SHA256、上传者、来源、Space。
4. 创建解析任务，将文件转换为 Graphify 可处理的材料。
5. 创建 Graphify 任务，输出 Wiki 草稿、图谱和报告。
6. 系统将新页面或候选更新同步到 Docmost。
7. 编辑者审核或修订页面。
8. 发布页面后触发索引更新。

### 6.2 人工修订流程

1. 用户在 Docmost 编辑 Wiki 页面。
2. Bridge 监听变更或定时导出。
3. Bridge 将页面转换为规范 Markdown。
4. 写入 Canonical Wiki Repo 并生成版本。
5. 触发受影响页面的 Graphify update 和索引刷新。
6. Chat 检索使用新版本页面。

### 6.3 GraphRAG 回答流程

1. 用户提问。
2. 系统识别问题意图和实体。
3. 系统获取用户可访问的 Space/KB scope。
4. 并行执行向量检索、关键词检索、图谱检索。
5. 对候选结果进行 ACL 过滤和 rerank。
6. 组装上下文，优先使用已发布 Wiki 页面和高置信图谱关系。
7. LLM 生成回答。
8. 返回回答、引用、图谱路径和置信说明。

## 7. 页面需求

### 7.1 Cherry Web 首页

- 最近会话。
- 有权限的 Spaces。
- 推荐 Wiki 页面。
- 最近更新知识。
- Graphify 任务状态摘要。

### 7.2 Chat 页面

- 模型选择。
- Space/知识范围选择。
- MCP/Agent 开关。
- 知识引用侧栏。
- 图谱路径解释。
- “反馈不准确”按钮，反馈进入知识治理。

### 7.3 Wiki 页面

由 Docmost 承载，但需要嵌入或旁路集成：

- 页面 Graphify 状态。
- 页面引用的源文件。
- 相关图谱节点。
- 相关 Wiki 页面。
- Graphify 候选更新提示。
- 页面索引状态。

### 7.4 管理后台

- 用户管理。
- Group 管理。
- Space 管理。
- 模型管理。
- Graphify 任务。
- 上传归档。
- 索引版本。
- 审计日志。
- 系统配置。

## 8. 非功能需求

| 类别 | 需求 |
|---|---|
| 可用性 | 核心聊天、Wiki 浏览和编辑应在单服务失败时有明确降级提示。 |
| 性能 | 普通聊天首 token 不超过 5 秒为目标；GraphRAG 检索不超过 2 秒为目标。 |
| 可扩展性 | 支持按 Space 分片运行 Graphify 和索引任务。 |
| 可观测性 | 所有任务、请求、模型调用、检索链路需有 trace_id。 |
| 安全 | 权限贯穿上传、页面、索引、图谱、回答引用。 |
| 合规 | AGPL 组件二开需提供源代码入口和许可证声明。 |
| 可维护性 | 所有模块 API 化，禁止跨模块直接访问内部表。 |

## 9. 验收摘要

Phase 1 验收必须覆盖：

1. Docker Compose 一键启动（不含 Docmost）。
2. 用户、分组、Space 权限。
3. 上传资料 → Graphify → Canonical Wiki Repo → Published Wiki。
4. Cherry Web 只读 Wiki 浏览。
5. Graphify 自动运行并生成图谱。
6. 对 Published Wiki 做向量 + BM25 索引。
7. Chat 基于 Wiki 索引回答并引用 Wiki 页面。
8. 无权限用户无法检索或看到无权限内容。
9. 任务、模型调用、索引版本和审计日志可查。

> Docmost 页面编辑、双向同步、Bridge 回写为 Phase 2 验收内容。
