# 14. 测试与验收规范

## 1. 测试目标

1. 确保 Graphify Wiki 唯一知识源原则不被破坏。
2. 确保权限贯穿上传、Wiki、Graphify、索引、聊天。
3. 确保 Graphify 后台任务可靠。
4. 确保 Docmost 同步可追踪、可恢复。
5. 确保 Chat GraphRAG 回答可引用、可解释。

## 2. 测试层级

| 层级 | 内容 |
|---|---|
| 单元测试 | 函数、service、parser、ACL、merge。 |
| 集成测试 | API + DB + Queue + Worker。 |
| 端到端测试 | 上传 → Graphify → Docmost → 编辑 → Chat。 |
| 权限测试 | 跨 Space、跨 Group、无权限图谱路径。 |
| 性能测试 | 检索延迟、聊天首 token、Graphify 任务吞吐。 |
| 安全测试 | 上传安全、ZIP、路径穿越、密钥泄露。 |
| 回归测试 | 版本升级、Schema migration、Graphify 输出变化。 |

## 3. 核心验收场景

### 3.1 上传生成 Wiki

前置：用户 A 有 `space_rd` 上传和编辑权限。  
步骤：

1. 上传 `sso-design.pdf`。
2. 等待解析完成。
3. 等待 Graphify run 完成。
4. 查看 Docmost 是否出现新页面。
5. 发布页面。
6. 在 Chat 中询问 SSO 流程。

期望：

- Source Archive 有原文件。
- Canonical Wiki Repo 有页面。
- Docmost 有页面。
- Graphify run 有 `graph.json` 和 report。
- Chat 回答引用该 Wiki 页面。

### 3.2 人工修订同步

步骤：

1. 在 Docmost 修改页面中的人工区块。
2. 保存。
3. Bridge 同步回 Repo。
4. 触发 Graphify update。
5. 重新提问。

期望：

- Repo 产生新版本。
- 人工区块未被 Graphify 覆盖。
- Chat 使用新版本。

### 3.3 权限隔离

前置：用户 A 属于 RD，用户 B 属于 Legal。  
步骤：

1. RD 上传资料并生成页面。
2. 用户 B 在 Chat 提问相关内容。
3. 用户 B 尝试访问引用页面。
4. 用户 B 尝试图谱搜索相关节点。

期望：

- 用户 B 不获得 RD 内容。
- 图谱路径中无 RD 节点。
- 审计记录权限拒绝。

### 3.4 Graphify 失败回滚

步骤：

1. 构造 Graphify 失败任务。
2. 检查上一版本索引是否可用。
3. 重试任务。

期望：

- 失败不影响已发布 Chat。
- 任务状态和错误可见。
- 重试成功后更新索引。

### 3.5 候选更新冲突

步骤：

1. 人工修改某页面的 human 区块。
2. 上传新资料触发 Graphify 生成同一页面更新。
3. 检查合并结果。

期望：

- human 区块未覆盖。
- Graphify 更新进入 proposal。
- 编辑者可接受/拒绝。

## 4. 单元测试清单

| 模块 | 测试 |
|---|---|
| wiki-core | Frontmatter 解析、区块所有权、diff merge。 |
| graph-core | graph.json parser、node/edge import、path query。 |
| auth-core | ACL envelope、Group 权限、Space scope。 |
| rag-core | candidate merge、rerank、context packing。 |
| job-core | 状态机、重试、幂等。 |
| ingestion | 文件类型识别、ZIP 安全、去重。 |

## 5. 集成测试清单

1. API 登录后创建 Space。
2. Space 绑定 Docmost Space。
3. 上传资料创建 ingestion job。
4. ingestion job 创建 graphify job。
5. graphify output 导入 DB。
6. indexer 生成 chunks 和 embeddings。
7. chat API 返回 citations。

## 6. 性能指标

Phase 1 目标：

| 指标 | 目标 |
|---|---|
| Chat 检索耗时 | P95 < 2s。 |
| Chat 首 token | P95 < 5s。 |
| Wiki 页面打开 | P95 < 1.5s。 |
| 小文件上传到页面草稿 | < 5min。 |
| 100 页 Wiki 重建索引 | < 10min，视模型和硬件调整。 |

## 7. 安全测试

1. ZIP 路径穿越。
2. 上传可执行文件伪装为 PDF。
3. Docmost 页面 Frontmatter 篡改 space_id。
4. Chat 请求传入无权限 space_id。
5. 图谱路径跨空间泄漏。
6. 日志中是否出现 API key。
7. Graphify 输入目录路径注入。

## 8. 验收门禁

上线前必须通过：

- P0 功能验收。
- 权限回归测试。
- 上传安全测试。
- Graphify 失败回滚测试。
- Docmost 同步一致性测试。
- AGPL/许可证声明检查。

## 10. 性能指标细化

> 本节合并 TODO T-5.4.1，覆盖第 6 节原始指标口径。

### 10.1 基准数据集

| 指标 | Phase 1 基准 |
|---|---:|
| 并发用户 | 10 |
| Wiki 页面 | 1000 |
| 图节点 | 5000 |
| 图边 | 10000 |
| 单页平均 chunk | 5 |
| 上传文档样本 | 100 页 PDF / DOCX 混合 |

### 10.2 Chat 与检索性能

| 指标 | Phase 1 目标 | Phase 3 优化目标 |
|---|---:|---:|
| Chat 首 token | P95 < 3s | P95 < 2s |
| 纯向量检索 | P95 < 500ms | P95 < 300ms |
| BM25 检索 | P95 < 500ms | P95 < 300ms |
| 混合检索 Vector + BM25 | P95 < 1.0s | P95 < 800ms |
| GraphRAG 混合检索 Vector + BM25 + Graph | Phase 1 不要求 | P95 < 1.5s |
| 含 ACL 过滤的完整检索 | P95 < 2s | P95 < 1.5s |
| Wiki 页面打开 | P95 < 1.5s | P95 < 1s |

### 10.3 Graphify 与索引性能

| 指标 | 目标 |
|---|---:|
| 100 页文档 → Wiki 生成 | < 30min |
| 1000 页 Wiki 全量索引 | < 15min |
| 单页面编辑后增量索引 | < 2min |
| Graphify 失败后恢复上一版本 | 立即可用 |
| 一致性检查 1000 页 | < 5min |

### 10.4 压测场景

1. 10 并发用户同时提问，同一 Space。
2. 10 并发用户跨 3 个 Space 提问，验证 ACL。
3. 1000 页 Wiki 全量重建索引期间继续 Chat。
4. Graphify run 进行中触发 Docmost 页面保存。
5. 权限变更后 30 秒内 Chat 结果不再包含撤权 Space。
