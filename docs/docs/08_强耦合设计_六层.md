# 08. 强耦合设计：六层

## 1. 总体说明

Graphify 与 Cherry Web 的集成不能停留在“配置一个 MCP 工具”。本项目要求强耦合，即 Graphify 参与知识源、索引、检索、UI、Agent 和权限全链路。

六层如下：

```text
1. 数据源耦合
2. 索引耦合
3. 检索耦合
4. UI 耦合
5. Agent 耦合
6. 权限耦合
```

## 2. 第一层：数据源耦合

### 2.1 目标

Graphify Wiki 成为 Cherry Web 唯一知识源。Cherry Web 不再把 PDF、DOCX、网页、纯文本等作为独立知识源直接检索，而是统一通过 Graphify Wiki 发布流程进入知识层。

### 2.2 设计

```text
Source Archive
  → Graphify Input
  → Graphify Wiki
  → Published Wiki
  → Indexable Source
```

Cherry Knowledge Source 类型：

| 类型 | 是否直接可检索 | 说明 |
|---|---|---|
| Graphify Wiki Page | 是 | 唯一可直接检索源。 |
| Graphify Graph Node/Edge | 是 | 从 Wiki 派生，必须有页面来源。 |
| Source Document | 否 | 只作为证据和再生成输入。 |
| Docmost Page | 否 | 需同步为 Canonical Wiki Page 后才可检索。 |
| Uploaded Attachment | 否 | 需解析和生成 Wiki。 |

### 2.3 需求

1. 所有知识库入口最终都必须写入 Canonical Wiki Repo。
2. 所有检索结果必须关联 `page_id` 和 `page_version`。
3. 源文件只可通过 Wiki 引用链访问。

## 3. 第二层：索引耦合

### 3.1 目标

Graphify 输出不只存文件，而要被解析为平台数据模型。

### 3.2 索引对象

```text
Wiki Page        → page_versions
Wiki Section     → wiki_sections
Text Chunk       → wiki_chunks + embeddings
Graph Node       → graph_nodes
Graph Edge       → graph_edges
Community        → graph_communities
Graph Report     → graph_reports
Source Mapping   → citations/source_links
```

### 3.3 索引规则

1. Chunk 必须来自 Published Wiki。
2. graph_node 必须至少关联一个 page_id 或 source_document_id。
3. graph_edge 必须有置信度、来源、运行 ID。
4. AMBIGUOUS 边默认不进入普通检索，只进入审核或解释层。
5. 索引版本与 Wiki 页面版本绑定。

## 4. 第三层：检索耦合

### 4.1 目标

聊天检索使用混合检索：Vector + BM25 + Graph。

### 4.2 检索流水线

```text
query
  → query rewrite/entity extraction
  → ACL scope resolution
  → vector search
  → BM25 search
  → graph entity/path/community search
  → candidate merge
  → ACL filter
  → rerank
  → context packing
  → answer generation
```

### 4.3 Graphify 检索能力映射

| Graphify 能力 | 平台使用方式 |
|---|---|
| `GRAPH_REPORT.md` | Space 高层摘要和问题推荐。 |
| `graph.json` | 导入 graph tables。 |
| `graphify query` | 后台工具或调试工具，生产可用 graph-core 复现。 |
| `graphify path` | 答案解释和路径证明。 |
| `graphify explain` | 节点说明。 |
| `--mcp` | Agent 工具补充。 |

## 5. 第四层：UI 耦合

### 5.1 Chat UI

回答展示：

- Wiki 引用。
- 页面版本。
- 相关图谱路径。
- 置信标签。
- “查看证据链”。
- “报告知识问题”。

### 5.2 Wiki UI

在 Docmost 页面旁展示：

- Graphify 运行状态。
- 索引状态。
- 来源文件。
- 相关节点。
- 相关页面。
- 候选更新。
- 低置信关系。

### 5.3 Admin UI

展示：

- Graphify run 列表。
- 节点/边数量。
- 社区分布。
- 孤立节点。
- 重复页面建议。
- 失败任务。

## 6. 第五层：Agent 耦合

### 6.1 目标

Agent 不只是查文档，还能调用图谱工具、Wiki 工具和任务工具。

### 6.2 工具清单

| 工具 | 说明 |
|---|---|
| `search_wiki` | 搜索 Published Wiki。 |
| `get_wiki_page` | 获取页面版本。 |
| `query_graph` | 查询图谱子图。 |
| `shortest_path` | 查节点路径。 |
| `get_node_neighbors` | 查相邻节点。 |
| `propose_wiki_update` | 生成 Wiki 更新建议。 |
| `create_graphify_job` | 管理员可触发 Graphify。 |
| `get_graphify_run` | 查看任务结果。 |

### 6.3 MCP 策略

Graphify MCP 和 Docmost MCP 可作为外部工具兼容层，但平台内部应优先调用自身 API 和数据库索引。

```text
平台主链路：Cherry API → graph-core/rag-core → indexes
Agent 兼容链路：MCP Gateway → Graphify MCP / Docmost MCP
```

## 7. 第六层：权限耦合

### 7.1 目标

权限不能只控制页面访问，还必须控制 chunk、节点、边、路径和引用。

### 7.2 ACL Envelope

所有索引对象必须带 ACL：

```json
{
  "tenant_id": "tenant_001",
  "space_id": "space_rd",
  "allowed_group_ids": ["group_rd"],
  "classification": "internal",
  "page_id": "rd.auth.sso",
  "page_version": 12
}
```

### 7.3 权限检查点

1. 上传前。
2. Docmost 编辑前。
3. Graphify job 创建前。
4. 页面发布前。
5. 索引写入前。
6. 检索查询前。
7. 候选合并后。
8. 回答引用前。
9. 图谱路径展示前。

## 8. 六层验收矩阵

| 层 | MVP 验收 |
|---|---|
| 数据源 | Chat 无法检索未发布 Wiki 或原始上传文件。 |
| 索引 | graph.json 被导入 graph_nodes/edges，chunk 绑定 page_version。 |
| 检索 | 回答使用 vector + BM25 + graph 至少两类结果。 |
| UI | 回答显示 Wiki 引用和图谱路径。 |
| Agent | 至少支持 query_graph 和 search_wiki 两个工具。 |
| 权限 | 无权限 Space 的节点、边、引用均不可见。 |
