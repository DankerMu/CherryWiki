# 18. 开源许可证与合规说明

> 本文不是法律意见，只是工程合规提醒。正式上线前应由法务或开源合规负责人确认。

## 1. Cherry Studio

Cherry Studio 社区版 README 和 LICENSE 显示其采用 GNU Affero General Public License v3.0，即 AGPL-3.0。AGPL 专门面向网络服务场景，要求修改版通过网络与用户交互时，向这些用户提供相应源代码访问方式。

本项目选择 Fork Cherry Studio 并重构 Web 版，因此必须处理：

1. 保留原项目版权和许可证声明。
2. 修改版继续遵守 AGPL。
3. Web 界面提供合适的法律声明和源码获取入口。
4. 若不希望承担 AGPL 义务，需要与原项目方沟通商业授权。

## 2. Docmost

Docmost GitHub README 显示其 core 使用 AGPL-3.0，Enterprise 功能采用单独企业许可。官方文档说明 REST API 和 MCP 是 Enterprise 功能，需要有效企业许可。

本项目使用 Docmost 时有三条路线：

| 路线 | 合规注意 |
|---|---|
| 使用开源 core 并 Fork | 遵守 AGPL，二开源码开放给网络交互用户。 |
| 使用 Enterprise | 遵守企业许可条款，确认 API/MCP 使用范围。 |
| 只做导入导出 | 仍需遵守 Docmost core AGPL。 |

## 3. Graphify

Graphify GitHub 页面显示其为 MIT license。MIT 对集成和二开更宽松，但仍需保留版权和许可声明。

注意：Graphify 作为 CLI/库被后台调用时，仍需保留其许可证文件和依赖许可证清单。

## 4. 第三方依赖

必须维护：

1. 前端依赖许可证清单。
2. 后端依赖许可证清单。
3. Python Worker 依赖许可证清单。
4. Docker 镜像 SBOM。
5. 源码中的第三方代码声明。

## 5. 合规功能需求

平台 UI 应包含：

1. 关于页面。
2. 开源许可证页面。
3. 修改源码获取方式。
4. 第三方组件列表。
5. 无担保声明。

## 6. 代码库要求

1. 保留 Cherry Studio 原始 LICENSE。
2. 保留 Docmost 原始 LICENSE，如 Fork。
3. 保留 Graphify LICENSE。
4. 所有修改文件注明修改日期和修改方，至少通过 Git 历史可追踪。
5. 镜像发布时附带 license bundle。

## 7. 发布前合规 Checklist

- [ ] Cherry Studio AGPL 义务确认。
- [ ] Docmost AGPL/Enterprise 授权确认。
- [ ] Graphify MIT license 已保留。
- [ ] 第三方依赖 SBOM 已生成。
- [ ] Web UI 已提供许可证和源码入口。
- [ ] 商业使用、内部分发、外部访问边界已确认。
- [ ] 管理员文档包含许可证说明。
