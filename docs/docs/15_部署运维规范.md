# 15. 部署与运维规范

## 1. 部署目标

1. Docker Compose 可启动全套 MVP。
2. 支持服务独立扩缩容。
3. 支持数据持久化、备份和恢复。
4. 支持健康检查、日志和监控。
5. 支持未来迁移 Kubernetes。

## 2. 服务清单

| 服务 | 说明 |
|---|---|
| `cherry-web` | 用户前端。 |
| `cherry-admin` | 管理后台，可与 web 合并。 |
| `cherry-api` | 后端 API。 |
| `graphify-worker` | Graphify 后台任务。 |
| `ingestion-worker` | 上传资料解析。 |
| `wiki-sync-worker` | Docmost 与 Canonical Wiki Repo 同步。 |
| `indexer-worker` | chunk、embedding、graph index。 |
| `docmost` | Wiki UI。 |
| `postgres` | 主数据库。 |
| `redis` | 队列和缓存。 |
| `minio` | 对象存储。 |
| `nginx` | 反向代理。 |

## 6. 数据持久化

必须持久化：

- PostgreSQL 数据。
- MinIO 数据。
- Redis AOF，至少任务队列需要。
- Canonical Wiki Repo。
- Graphify 输出。
- Docmost storage。

## 7. 备份策略

| 数据 | 频率 | 说明 |
|---|---|---|
| PostgreSQL | 每日全量 + WAL | 包含业务元数据和页面版本。 |
| MinIO | 每日同步 | 原始资料和 Graphify 输出。 |
| Wiki Repo | 每次 commit + 每日镜像 | 可直接 Git 备份。 |
| Docmost DB/storage | 每日 | 与 Wiki Repo 一起校验。 |
| Redis | 可选 | 队列可重建时无需长期保留。 |

## 8. 恢复流程

1. 恢复 PostgreSQL。
2. 恢复 MinIO。
3. 恢复 Wiki Repo。
4. 恢复 Docmost。
5. 启动 API 和 Worker。
6. 执行索引一致性检查。
7. 必要时重建索引。

## 9. 日志与监控

必须监控：

- API QPS、错误率、延迟。
- Chat 首 token 时间。
- 模型调用耗时和失败率。
- Graphify 任务耗时和失败率。
- 队列长度。
- 索引任务耗时。
- PostgreSQL 连接数。
- MinIO 存储容量。
- 权限拒绝异常波动。

## 10. Graphify Worker 运维

1. 每个 Worker 限制并发。
2. 大型 Space 单独队列。
3. 任务超时自动失败。
4. 输出文件过小或 graph 节点骤减时触发保护，不自动覆盖有效 graph。
5. Worker 容器不挂载宿主敏感目录。
6. 工作目录定期清理。

## 11. 升级策略

1. 先升级测试环境。
2. 备份 DB、Wiki Repo、MinIO。
3. 执行 migration dry-run。
4. 滚动升级 API 和前端。
5. 暂停 Worker 后升级 Worker。
6. 恢复 Worker 并执行索引一致性检查。

## 12. 故障处理

### 12.1 Graphify 失败

- 查看 run log。
- 检查输入 corpus。
- 检查模型调用。
- 重试。
- 如多次失败，回滚到上一 graph 版本。

### 12.2 Docmost 同步失败

- 检查 Bridge token。
- 检查页面 Frontmatter。
- 进入 sync_pending 队列重试。
- 必要时手动导出 Markdown 合并。

### 12.3 Chat 引用错误

- 查看 retrieval debug。
- 检查 page_version。
- 检查 chunk 与 graph ACL。
- 重新索引页面。

## 13. MVP 部署验收

1. `docker compose up -d` 后所有服务健康。
2. 可以登录 Cherry Web 和 Docmost。
3. 可以上传资料并完成 Graphify。
4. 可以编辑 Wiki 并同步。
5. 可以 Chat 并返回引用。
6. 停止某个 Worker 后任务不会丢失。
7. 重启后已发布知识仍可检索。
